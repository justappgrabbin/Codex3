# Build 0.1

This is the local foundation and a Three.js integration workbench. The target Unity world is represented through an engine-neutral entity contract; this is not a Unity build. The preview is deliberately a procedural engineering visualization: primitives, solid surfaces, visible particle assembly, and an articulated test body are code geometry, not final game art. No image-generated production art is required to evaluate this substrate.

Pure JavaScript ES modules; no runtime network, backend inference, API keys, Python, or remote model. The Node static server is only a file server; any static HTTP server works. Vendored Three.js 0.170.0 supplies WebGL rendering.

Recovered AutomataMesh, Automaton, StatePacket, and King Wen line-bit mapping are imported from the user's unified archive. New modules add strict DMSA validation, recursive composition, local frames, provenance-rich relations, explicit operators, deterministic event replay, and a three-door test world.

Do not use the donor global-address codec for natal charts: it assumes a sequential gate wheel and eight trigram houses. New addresses are explicit authored examples, validated against the document's local ranges, never presented as calculated natal data. No birth data is collected in this build. New canonical metadata fixes the donor's swapped When/Where association. New code does not depend on that donor dimensional metadata.

Space's pairwise expression rule is an explicit engineering hypothesis, not a derivation of the source cosmology. Signal edges strengthen as crossing_count/(crossing_count+1): activity memory, not a trained neural network. Four perspective entities exist and contribute inspectable qualities; they are local computational perspectives, not four deployed LLMs. The three branches are authored recipes assembled from shared primitives; this does not claim unseen arbitrary game generation.

Companion code with zero cross-block products was not imported. This build uses a shared relation graph with actual packet delivery. Realistic person reconstruction, segmentation, hidden-background completion, image/video generation, physical hand manipulation, astronomical chart/transit computation, and learned neural inference are not implemented.

UI inventory: full dark navy workbench, restrained warm type and mint focus color; large 3D canvas with three solid portals; left journey panel; right selectable entity inspector; bottom expandable provenance ledger. Tabs are Embodied and Function views of the same entities. Working controls: goal/pace, door entry, activities, return, entity selection, frame history, qualities, line change, operator execution, pause, sound, save/export/import, replay scrubber. Native system fonts; accessible labels, keyboard alternatives, responsive single-column continuation. No marketing page, placeholder image analysis, decorative fabricated metrics, or unsupported chart claims.
